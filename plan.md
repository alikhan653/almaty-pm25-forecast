## 1. Тема и формулировка

**Рабочее название:** "Интеллектуальная система краткосрочного прогнозирования качества воздуха в Алматы на основе открытых данных низкобюджетных сенсоров"
**Настоящее название** "Разработка интеллектуальной системы для исследования и решения экологических проблем"

**Уровень:** магистерская диссертация
**Срок реализации:** 1 месяц (4 недели)
**Автор:** Алихан, Алматы, Казахстан
**Язык диссертации:** английский (код, комментарии, README — английский)

## 2. Что делаем и чего не делаем

### Делаем
- Веб-приложение с одним экраном: карта Алматы + прогноз PM2.5 на 6/12/24 часа.
- ML-модель прогнозирования PM2.5 (XGBoost) на исторических данных за зимний сезон.
- Сравнение с тремя бейзлайнами: persistence, линейная регрессия, прогноз CAMS из Open-Meteo Air Quality API.
- Деплой на Streamlit Community Cloud (бесплатно).

### Сознательно НЕ делаем (отказались на этапе планирования)
- Облачная инфраструктура (AWS, оркестрация, CI/CD) — не нужно для научной задачи, добавляет 2 недели работы без новизны.
- Carbon-aware слой — был в ранних версиях, отказались как от не критичного.
- Персонализация (профиль пользователя, exposure assessment) — слишком сложно для месяца.
- Интеграция со спутником Sentinel-5P — оставлено как "перспективы" в Главе 4.
- SHAP-атрибуция источников — оставлено на доработку, если останется время после неделе 3.
- Мобильное приложение, push-уведомления, нативные приложения — PWA не нужен, веб достаточно.
- Регистрация пользователей, БД профилей, авторизация.

**Если в ходе работы появляется соблазн добавить что-то из этого списка — не добавляем без явного решения автора.**

## 3. Научная новизна (две точки)

1. **Локальная модель** прогнозирования PM2.5 для климатических условий Алматы (зимняя инверсия в горной чаше, угольное отопление частного сектора, малый ветер) — большинство существующих моделей разработаны для других географий.
2. **Воспроизводимая открытая архитектура** на базе только публичных данных (OpenAQ + Open-Meteo), что делает решение применимым к другим городам Центральной Азии (Шымкент, Караганда).

## 4. Технологический стек

### Обязательно
- **Python 3.11+**
- **uv** для управления зависимостями (быстрее pip)
- **pandas, numpy** — обработка данных
- **scikit-learn, xgboost, lightgbm** — ML
- **openaq** (официальный SDK) или прямые HTTP-запросы — забор данных о воздухе
- **requests** — Open-Meteo (нет официального SDK)
- **SQLite** — хранение (не PostgreSQL, упрощаем)
- **Streamlit** — веб-приложение
- **folium** или **pydeck** — карта Алматы
- **matplotlib, seaborn, plotly** — графики для диссертации

### Запрещено добавлять без согласования
- Docker, Kubernetes, любая контейнеризация
- AWS, GCP, Azure — любые облачные сервисы
- React, Vue, Next.js, любой кастомный фронтенд
- Postgres, Redis, Kafka — любые серверные БД и брокеры
- Airflow, Prefect, Dagster — оркестрация не нужна, хватит cron или ручного запуска

## 5. Источники данных (критичная информация)

### OpenAQ
- **URL:** https://api.openaq.org/v3
- **Авторизация:** API-ключ в заголовке `X-API-Key` (бесплатная регистрация на explore.openaq.org)
- **SDK:** `pip install openaq`
- **Покрытие Казахстана:** данные с 27 июля 2018, обновляются регулярно
- **Параметры:** PM2.5 (id=2), PM10 (id=1), PM1 (id=19), температура (id=100), влажность (id=98)
- **Поставщики данных в Алматы (по факту, день 2, 2026-04-20):** AirGradient (153 станции), Clarity (38), AirNow (1). Все три — **низкобюджетные сенсоры**, не референсные станции Казгидромета. Это нужно явно отметить в Главе 1 как ограничение и одновременно как часть научной новизны. (Ранее в плане было указано luftdaten.info — устаревшая информация, в текущем ответе OpenAQ его нет.)
- **Ограничение от OpenAQ 2024:** Казахстан и Турция делятся данными "только внутри страны" — но мы в Алматы, доступ открыт.
- **Лицензия:** CC BY 4.0
- **Запрос станций Алматы:** `GET /v3/locations?coordinates=43.25,76.93&radius=25000&limit=1000`
- **Пример запроса измерений:** `GET /v3/sensors/{sensor_id}/measurements?date_from=2024-11-01&date_to=2025-03-31`
- **Цитирование:** OpenAQ (2024). OpenAQ Platform. https://openaq.org

### Open-Meteo
- **URL forecast:** https://api.open-meteo.com/v1/forecast
- **URL историческая погода:** https://archive-api.open-meteo.com/v1/archive
- **URL качество воздуха (CAMS):** https://air-quality-api.open-meteo.com/v1/air-quality
- **Авторизация:** не нужна, без API-ключа
- **Лимит:** 10000 запросов/день для некоммерческого использования
- **Координаты Алматы:** 43.2389, 76.8897
- **Параметры для часовых данных:** `temperature_2m,relative_humidity_2m,pressure_msl,wind_speed_10m,wind_direction_10m,boundary_layer_height,precipitation`
- **boundary_layer_height (BLH)** — ключевой признак для Алматы! Низкий BLH зимой = инверсия = высокий PM2.5
- **CAMS PM2.5** — будем использовать как бейзлайн для сравнения с нашей моделью
- **Лицензия:** CC BY 4.0
- **Цитирование:** Zippenfenig, P. (2023). Open-Meteo.com Weather API. Zenodo. https://doi.org/10.5281/ZENODO.7970649

## 8. Решения, принятые на этапе планирования (не менять без обсуждения)

| Вопрос | Решение | Почему |
|---|---|---|
| Уровень амбиций | Минимальный жизнеспособный | 1 месяц, один человек |
| Город | Только Алматы | Хватает данных и доменной специфики |
| Загрязнитель | PM2.5 как основной, PM10 опционально | Самый health-критичный, лучше всего покрыт |
| Сезон | Зимний (нояб-март) | Острая проблема, отопление + инверсия |
| Окно обучения | 2024-10-01 — 2026-04-15 | День 2: только ~1 сенсор покрывал зиму 2023-24, большинство AirGradient появились в 2025. Обучаем на полном окне, фокус на зиме остаётся в анализе ошибок (Глава 3) и обсуждении (Глава 4) |
| Горизонт прогноза | 6, 12, 24 часа | Полезно жителю, реалистично по точности |
| Тип модели | XGBoost | Быстро, табличные данные, не нужен GPU |
| База данных | SQLite | Хватает, не требует сервера |
| Веб-стек | Streamlit | Минимум кода, Python-only |
| Деплой | Streamlit Community Cloud | Бесплатно, без DevOps |
| Источник данных воздуха | OpenAQ | Бесплатно, есть история, есть SDK |
| Источник погоды | Open-Meteo | Бесплатно, без ключа, есть BLH |
| Бейзлайны | persistence, linear, CAMS | Стандартные + сравнение с европейской моделью |
| Валидация | Time-series CV (rolling window) | Random split = утечка данных в time series |
